# v2.2 item C: `apply_code_fix` + `list_code_fixes`

## Design note

**One new package.** `Microsoft.CodeAnalysis.CSharp.Features` 5.6.0 (pulls in
`Microsoft.CodeAnalysis.Features`, `Elfie`, `Scripting`, `DiaSymReader`,
`ExternalAccess.RazorCompiler` transitively). This is the one new package reference the
v2.2 plan allows.

**Size impact** (`dotnet pack src/RoslynMcp -c Release`, same commit before/after):

| | before | after | delta |
|---|---:|---:|---:|
| `RoslynMcp.2.1.0.nupkg` | 10,871,877 B (10.4 MiB) | 15,271,940 B (14.6 MiB) | +4,400,063 B (+40%) |
| `bin/Release/net10.0/publish/` | 31,347,024 B, 67 entries | 43,773,173 B, 74 entries | +12.4 MB |

The two biggest additions are `Microsoft.CodeAnalysis.Features.dll` (5.6 MB) and
`Microsoft.CodeAnalysis.CSharp.Features.dll` (2.3 MB), plus their satellite resource folders.

**Provider discovery (`src/RoslynMcp/CodeFixCatalog.cs`).** Roslyn's code fix providers are
MEF exports, but nearly all have a parameterless (importing) constructor, so reflection is
enough: every non-abstract `CodeFixProvider` type in the two Features assemblies that carries
`[ExportCodeFixProvider(LanguageNames.CSharp, ...)]` is instantiated once (anything that
throws, or has no parameterless constructor, is skipped and recorded) and indexed by
`FixableDiagnosticIds`. 169 C# providers load on 5.6.0, none skipped. Providers for an id are
ordered by export name (ordinal) for determinism; Roslyn's `[ExtensionOrder]` attributes are
not honoured.

**MEF host: no change was needed.** Several providers (add-import, remove-unnecessary-imports)
resolve internal language services through the workspace's host. `WorkspaceHost` still calls
`MSBuildWorkspace.Create()` unchanged: on 5.6.0, `MSBuildMefHostServices.DefaultAssemblies`
(and `MefHostServices.DefaultAssemblies`) already list `Microsoft.CodeAnalysis.Features` and
`Microsoft.CodeAnalysis.CSharp.Features` and load them by name whenever they are deployed next
to the app. Verified two ways: printing `DefaultAssemblies` (Workspaces, CSharp.Workspaces,
Features, CSharp.Features), and running the full `ApplyCodeFixTests` with both the explicit
composition (`MefHostServices.Create(MSBuildMefHostServices.DefaultAssemblies.AddRange(features).Distinct())`)
and the default `Create()`: identical, all green. The explicit composition was therefore
dropped to keep `WorkspaceHost.cs` untouched. If a future Roslyn stops auto-including the
Features assemblies, the CS0246 test fails first (add-import offers nothing); the fix is that
one-line composition.

**Diagnostics source.** Compiler diagnostics only, from `SemanticModel.GetDiagnostics()` per
document (syntax, declaration and method-body diagnostics, plus the compiler's
unused-import pass), unsuppressed, Hidden included (`list_code_fixes` can drop Hidden with
`includeHidden: false`). Documents under `bin/` or `obj/` (generated `GlobalUsings.g.cs`,
`AssemblyInfo.cs`) are excluded. Visible this way, for example: CS8019 (unnecessary using,
Hidden), CS8933 (using duplicates a global using, Hidden), CS0219/CS0168 (unused locals),
CS0246 and every other compile error/warning. **Not** visible: analyzer-only IDE diagnostics
(IDE0005 as an analyzer, IDE0001, ...), because no analyzers are run. They did not "come
free": the IDE0005 analyzer would have to run through `CompilationWithAnalyzers`.

**CS8019 is fixed by the IDE0005 fixer, via an alias.** Roslyn's remove-unnecessary-usings
fixer (`CSharpRemoveUnnecessaryImportsCodeFixProvider`, export name `RemoveUnnecessaryImports`)
declares only the hidden companion id `RemoveUnnecessaryImportsFixable`, which its IDE0005
analyzer emits alongside IDE0005. The fixer ignores the diagnostic's details (it removes every
unnecessary using in the document via the remove-unnecessary-imports service, which uses the
same compiler information as CS8019). So `CodeFixCatalog` maps CS8019 to that id and the tool
hands CS8019 diagnostics to the fixer re-labelled. `list_code_fixes` reports this as
`fixedVia: "RemoveUnnecessaryImportsFixable"`. Callers may ask for `IDE0005` (or
`RemoveUnnecessaryImportsFixable`); it is normalised to CS8019.

**`apply_code_fix` mechanism (`src/RoslynMcp/Tools/CodeFixTools.cs`).**
1. Collect the matching diagnostics in scope (sorted by file, position), take the first
   `maxDiagnostics`.
2. Pick **one** provider: the first by name that offers a matching action (first action, or
   first whose title contains `fixTitle`) for any targeted diagnostic. Nested (grouped)
   actions are flattened to their leaves. Using a single provider keeps the fix uniform. For
   example, `CS0246` across FixtureLib uses AddImport for `NeedsImport.cs` and leaves the
   unresolvable `Broken.cs` alone. It does not quietly switch to Generate Type for that one.
3. If the provider has a `FixAllProvider` supporting the mapped scope (file to Document,
   project to Project, solution to Solution), run it with a `FixAllContext` whose
   `DiagnosticProvider` returns exactly the targeted diagnostics. Otherwise (or if FixAll
   yields nothing) go one diagnostic at a time per document, re-deriving the document's
   diagnostics from the evolving candidate after each fix so edits compose.
4. Each `CodeAction`'s operations must be exactly one `ApplyChangesOperation`. Anything else
   is refused with a clear message (nothing written).
5. `diagnosticsFixed` = targeted diagnostics no longer present in the candidate (per
   document, recomputed).
6. `MutationApplier.ApplyOrPreviewAsync(candidate, dryRun)`: staleness check + compile gate
   against the load-time baseline, same as every write tool.

**`changes` are whole-line hunks.** Roslyn's character-level text changes report a removed
using block as fragments spanning line boundaries (`"System.Text;\nusing System.Collections.Concurrent;\nusing "`).
`apply_code_fix` instead describes each changed document with a line-level LCS diff:
`{line, oldText, newText}` where `line` is 1-based in the old text and both texts include
their line breaks (so removing `using System.Net;` on line 4 is
`{line: 4, oldText: "using System.Net;\n", newText: ""}`). Files over 4M line pairs fall back
to the character-level description the other write tools use. Added documents (a fix that
creates a file) are applied and gated but not listed in `changes`.

**Proven end to end** (`tests/RoslynMcp.Tests/ApplyCodeFixTests.cs`, 9 tests):
- **CS8019 remove unnecessary usings** (provider `RemoveUnnecessaryImports`, FixAll): file
  scope removes exactly the three usings in `Fixable.cs` and keeps the used one (exact file
  text). The dry run writes nothing and its `changes` equal the real call's. Project and
  solution scope touch exactly `Box.cs`, `Fixable.cs`, `Shapes.cs` (the fixture's full CS8019
  answer key; `Box.cs`/`Shapes.cs` have a pre-existing `using System;` that duplicates the
  implicit global using). Every other fixture file hashes identical. The `IDE0005` alias works.
- **CS0246 add missing using** (provider `AddImport`, per diagnostic): adds exactly
  `using FixtureLib.Imports;` after the System usings in `NeedsImport.cs`. The gate accepts it
  and FixtureLib's errors drop from 2 to 1 (only `Broken.cs`'s planted CS0246 remains). At
  project scope `Broken.cs` (no candidate namespace) is left alone and reported as remaining.
- Unknown id: `applied: false`, "Not fixable: no Roslyn C# code fix provider handles ...".
  Fixable id with no occurrences (CS0168): `diagnosticsFound: 0`, `applied: false`.

**Fixture additions** (new files only): `FixtureLib/Fixable.cs`, `FixtureLib/NeedsImport.cs`,
`FixtureLib/Imports/Widget.cs`. The planted CS0246 lives in FixtureLib, which already carries
`Broken.cs`'s baseline CS0246, because existing tests assert that FixtureApp has zero
errors. No existing test needed changing.

**Known limits.**
- Compiler diagnostics only. Analyzer-only IDE diagnostics are not computed or fixable yet.
- Only the two fixes above are proven. Other providers are discovered and offered (e.g.
  CS0219 has `RemoveUnusedVariable`) but untested. They run with Roslyn's default code-action
  options (no `.editorconfig` code-style options are passed to fixers).
- Provider choice is by export name, not Roslyn's `[ExtensionOrder]`; use `fixTitle` to pick
  a specific action.
- One provider per call. Fixes needing non-text operations (e.g. NuGet package installs from
  add-import's package search, which is not enabled here) are refused.
- Generated documents (`bin/`, `obj/`, source generators) are never diagnosed or edited.

## README subsections (ready to paste)

### `apply_code_fix`

Applies one of Roslyn's own C# code fixes to every occurrence of a diagnostic id in a file,
project or the whole solution, then writes it through the same compile gate as every other
write tool (refused if it would introduce a new compile error, or if a touched file changed
on disk since load). Proven fixes: **CS8019** (remove unnecessary usings; `IDE0005` is accepted
as an alias) and **CS0246** (add the missing `using` when the type exists in exactly one
namespace in the solution). Uses the provider's FixAll where it supports the scope, otherwise
fixes one diagnostic at a time and composes the edits.

| Parameter | Default | Meaning |
|---|---|---|
| `diagnosticId` | (required) | e.g. `CS8019`, `CS0246` |
| `scope` | `solution` | `file`, `project` or `solution` |
| `filePath` | | required for `scope: file`; for `scope: project` selects the file's project |
| `projectName` | | for `scope: project` |
| `fixTitle` | first action | pick among several actions by title substring, e.g. `using FixtureLib.Imports` |
| `maxDiagnostics` | 500 | fix at most this many occurrences |
| `dryRun` | false | compute + gate, report the exact changes, write nothing |

Returns `diagnosticId, scope, diagnosticsFound, diagnosticsFixed, fixTitle, provider, applied,
dryRun, wouldApply, changedFileCount, changes, conflicts, staleFile, message`. `changes` lists
whole-line hunks per file (`{line, oldText, newText}`, texts include their line breaks). An id
with no Roslyn fixer returns `applied: false` with a "Not fixable" message; an id with no
occurrences in scope returns `diagnosticsFound: 0`.

```jsonc
// apply_code_fix { "diagnosticId": "CS8019", "scope": "file", "filePath": ".../Fixable.cs", "dryRun": true }
{ "diagnosticId": "CS8019", "scope": "file", "diagnosticsFound": 3, "diagnosticsFixed": 3,
  "fixTitle": "Remove unnecessary usings", "provider": "RemoveUnnecessaryImports", "fixAll": true,
  "applied": false, "dryRun": true, "wouldApply": true, "changedFileCount": 1,
  "changes": [{ "file": ".../Fixable.cs", "edits": [
    { "line": 1, "oldText": "using System.Text;\nusing System.Collections.Concurrent;\n", "newText": "" },
    { "line": 4, "oldText": "using System.Net;\n", "newText": "" } ] }],
  "message": "Dry run: the edit would be applied; 1 file(s) would change. Nothing was written." }
```

### `list_code_fixes` (read-only)

Lists the compiler diagnostics in a file, project or the solution, Hidden severity included
by default (so CS8019 unnecessary usings show up), grouped by id with a count and up to 20
locations each, and for each id whether a Roslyn code fix exists: `fixable`, `providers`,
`fixAllSupported` (and `fixedVia` when the fixer is registered under another id, as with
CS8019). Parameters: `diagnosticId?`, `scope` (`file` | `project` | `solution`, default
`solution`), `filePath?`, `projectName?`, `includeHidden` (default true). Ordering is
deterministic (ids ordinal; locations by file, then position). Analyzer-only IDE diagnostics
are not computed, and files under `bin/` and `obj/` are excluded.
