# v2.2 item B: `analyze_change_impact`

## Design note

`analyze_change_impact` answers "if I change this, what else is affected, what has to
recompile, and which tests should I run?" in one read-only call. It is a multi-source
breadth-first walk over the reverse dependency graph, starting from one or more targets.

**Edges (what counts as a dependent).**
- Callable targets and nodes (method, constructor, property, event): the dispatch-aware
  caller edges from `find_callers`, unchanged. The tool reuses `HierarchyTools.CallerWalker`
  directly (its `GetCallerEdgesAsync` and `GetDispatchGroupAsync` are now `internal`), so
  callers through a base or interface declaration carry the same `via` label, and
  `base.X()` calls are excluded the same way.
- Overrides and implementations of a callable target (`relation: "override"` /
  `"implementation"`) are dependents at distance 1, because changing the contract affects them.
  This applies only to targets: an override of some caller further up doesn't depend on the target.
- Types and fields: `SymbolFinder.FindReferencesAsync`, with each reference mapped to the
  member that contains it (method, property, field, event, or, for base lists and type-level
  attributes, the type itself). References inside the target type's own members are dropped,
  since they are part of the type and not dependents of it. Later levels follow callers
  for callable nodes and references for non-callable nodes.

**Shortest paths.** All targets start at distance 0 and the first discovery wins, so each
node's `distance` is its shortest distance to any target, and following parent pointers gives
a shortest path. Each test's `path` is that chain, running from the test down to the target. Ties are
broken by the deterministic edge order (file path ordinal, then position), the same order
`find_callers` uses.

**Tests.** A dependent method is a test if it has an attribute whose short name, with or
without the `Attribute` suffix, is `Fact`, `Theory`, `Test`, `TestCase`, `TestMethod`,
`SkippableFact` or `SkippableTheory`. Matching is by name, not by framework type, so
xUnit, NUnit, MSTest and look-alike custom attributes are all detected. A target that is
itself a test isn't listed in `tests`.

**Caps.** `depth` (default 3, max 10) bounds the number of levels. Nodes at distance `depth`
aren't expanded. `maxNodes` (default 500, max 5000) caps the number of *unique* dependents
discovered. When the walk needs more, it stops and reports `truncated: true`. `nodeCount` is the number of
dependents. This differs slightly from `find_callers`, which counts tree nodes including
repeats, because the impact report is a set and not a tree.

**projectsToRecompile.** The projects that own the target declarations, plus everything
`Solution.GetProjectDependencyGraph().GetProjectsThatTransitivelyDependOnThisProject`
returns, sorted by name. This list comes from the project graph alone, so it is listed even
when nothing references the target (a change to an unused public member still rebuilds downstream).

**Ordering.** `dependents` groups are sorted by project name. Members in a group, and the
`tests` list, are sorted by project, then file path (ordinal), then position. The same input
always gives byte-identical output, and a position-based call gives the same output as the
equivalent `fullyQualifiedName` call.

**Refactor of HierarchyTools.** No behaviour change. These members went from `private` to
`internal` so the two tools share one implementation: `ViaFormat`, `NormalizeCaller`,
`Key`, `GetEntryPointKeysAsync`, `DescribeSymbol`, the `DispatchMember`/`CallerEdge` records,
the `CallerWalker` class, and `CallerWalker.GetCallerEdgesAsync` (now `public` inside the
internal class). `DeletionTools.IsExternallyVisible` also became `internal` so it can be reused for the `note`.

**Fixture.** `fixtures/ImpactSolution` (ImpactLib, ImpactApp -> ImpactLib, ImpactTests ->
ImpactLib; xunit 2.9.2, Test.Sdk 17.12.0, runner 2.8.2, so restore uses the local cache).
It is a separate solution so that FixtureSolution's `projectCount == 2` assertions stay untouched.
The answer key is in the comment block at the top of `tests/RoslynMcp.Tests/AnalyzeChangeImpactTests.cs`.

## README subsection (ready to paste)

### `analyze_change_impact` (read-only)

Shows the blast radius of changing a symbol before you change it: who depends on it,
which projects rebuild, and which tests to run. Identify the symbol by
`filePath`+`line`+`column`, by `fullyQualifiedName`, or by a batch in `fullyQualifiedNames`
(analyzed as one change). Works for methods, constructors, properties, events, fields and types.

- `dependents`: transitive dependents up to `depth` (default 3, max 10), grouped by
  project. These are callers (dispatch-aware, the same edges as `find_callers`, with `via` when a
  call goes through a base or interface member), overrides and implementations of the target, and for
  types and fields every member that references them. Each entry has `distance`, `relation`
  (`caller` / `reference` / `override` / `implementation`) and `reaches` (the next hop toward
  the target).
- `projectsToRecompile`: the target's project plus every project that transitively depends on it.
- `tests`: test methods that reach a target within `depth`, each with the shortest call path
  from the test down to the target.
- `maxNodes` (default 500, max 5000) caps the dependents. `truncated: true` means the cap was hit.

```json
{
  "targets": [{ "name": "Execute", "kind": "Method", "display": "ImpactLib.Pipeline.Execute(ImpactLib.IStage, string)", "containingType": "ImpactLib.Pipeline" }],
  "depth": 3,
  "nodeCount": 5,
  "truncated": false,
  "projectsToRecompile": ["ImpactApp", "ImpactLib", "ImpactTests"],
  "dependents": [
    { "project": "ImpactApp", "members": [
      { "symbol": "ImpactApp.Program.Main", "kind": "Method", "relation": "caller", "file": ".../Program.cs", "line": 7, "column": 24, "distance": 1, "reaches": "ImpactLib.Pipeline.Execute", "isEntryPoint": true } ] },
    { "project": "ImpactTests", "members": [
      { "symbol": "ImpactTests.PipelineTests.ExecuteViaHelper", "kind": "Method", "relation": "caller", "file": ".../PipelineTests.cs", "line": 15, "column": 17, "distance": 2, "reaches": "ImpactTests.PipelineTests.RunTrim" } ] }
  ],
  "tests": [
    { "symbol": "ImpactTests.PipelineTests.ExecuteViaHelper", "project": "ImpactTests", "file": ".../PipelineTests.cs", "line": 15, "column": 17, "distance": 2,
      "path": ["ImpactTests.PipelineTests.ExecuteViaHelper", "ImpactTests.PipelineTests.RunTrim", "ImpactLib.Pipeline.Execute"] }
  ],
  "note": "At least one target is publicly visible: dependents were found only inside the loaded solution. External consumers (...) can't be seen."
}
```

Limits:
- Only the loaded solution is visible. Consumers in other repositories or packages are not, and
  a `note` says so when a target is publicly visible.
- Reflection, DI registration, serialization and source-generated wiring are invisible. A
  dependency that exists only at runtime won't show up.
- Test detection is by attribute name (`Fact`, `Theory`, `Test`, `TestCase`, `TestMethod`,
  `SkippableFact`, `SkippableTheory`). Tests discovered by convention or by custom attributes with
  other names are missed, and tests that reach the target only through reflection or DI are missed too.
- Interface and virtual dispatch over-approximates. A test that calls `Pipeline.Execute`
  is reported for every `IStage.Run` implementation, not only the one it passes at runtime.
