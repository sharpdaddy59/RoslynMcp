# v2.2 item E: generation after extraction

`implement_interface`, `implement_abstract`, `generate_overrides` (src/RoslynMcp/Tools/ImplementationTools.cs).

## Design note

**One pipeline, three member pickers.** Each tool resolves the target type (position or
fully-qualified name; a position on a member means its containing type; class or struct,
declared in source), decides which members to generate, and hands the list to one shared
insertion stage. They differ only in how they pick:

- `implement_interface`: the interfaces in the type's base list (or only `interfaceName`,
  matched by simple name `IRepository`, constructed `IRepository<string>` or fully-qualified
  name), each expanded with its base interfaces (`AllInterfaces`), deduplicated. A member is
  missing when `INamedTypeSymbol.FindImplementationForInterfaceMember` returns null, so
  members already satisfied by a base class, and default interface implementations, count as
  implemented. Only abstract interface members are candidates (non-abstract statics and
  default implementations are skipped). In implicit mode two interface members with the same
  signature produce one stub.
- `implement_abstract` / `generate_overrides`: one walk of the base chain. Every member of the
  type itself, together with its whole `Overridden*` chain, is marked covered; then each base
  type is visited nearest-first and every not-yet-covered ordinary method, property, indexer or
  event that is abstract, virtual or a non-sealed override (and accessible from the type) is a
  candidate. Visiting a member always covers its chain, so a sealed override hides the virtual
  it seals and an intermediate override hides the original. `implement_abstract` takes the
  abstract candidates, `generate_overrides` the rest.

**Stubs via SyntaxGenerator.** Each member is built from its symbol (`MethodDeclaration`,
`PropertyDeclaration`, `IndexerDeclaration`, `EventDeclaration`, `CustomEventDeclaration`),
then `WithModifiers` resets the modifiers (none, `static`, or `override`) and
`WithAccessibility` sets `public` (interface) or the base member's accessibility (override;
`protected internal` from another assembly becomes `protected`). Bodies:
`throw new NotImplementedException();` for `implement_interface` / `implement_abstract`
(property and indexer getters and setters each throw, explicit events throw in add/remove),
and base calls for `generate_overrides` (`return base.X(args);`, `base.X(args);`,
`return base.P;` / `base.P = value;`, `base[i]`, `base.E += value;`), so an override never
silently changes behaviour and a generated `ToString` is not a trap. `explicitly: true` goes
through `AsPrivateInterfaceImplementation`. Constraint clauses are stripped from override and
explicit generic methods (repeating them is CS0460).

**Insertion and formatting.** Stubs are appended (`SyntaxGenerator.AddMembers`) to the type's
FIRST declaration, i.e. `DeclaringSyntaxReferences[0]`, the compiler's document order. Each
inserted node carries `Simplifier.Annotation` and `Formatter.Annotation`, then
`Simplifier.ReduceAsync` (turns `global::System.String` into `string`, drops redundant
qualification) and `Formatter.FormatAsync(document, Formatter.Annotation)` run on the
inserted nodes only: the rest of the file is untouched byte-for-byte. Partial types report
`insertedInto` plus `partialDeclarationFiles` and a message naming the file.

**Doc comments go in as text.** After formatting, each stub (found again by its own
annotation) gets the contract member's source XML doc comment, re-indented line by line, or
`/// <inheritdoc />` when the contract has none in source (metadata members such as
`object.ToString`). The candidate is then built with `Solution.WithDocumentText`, a clean
re-parse of exactly what will be written. This is the same trap `extract_interface` documents:
structured doc-comment trivia moved between trees corrupts the compiler's doc bookkeeping
(spurious CS1569), so it is never attached as nodes.

**`using System;` only when needed.** Before inserting, the tool asks the semantic model
whether `NotImplementedException` resolves at the type's closing brace
(`LookupNamespacesAndTypes`); implicit global usings count. Only when it does not is
`using System;` added (`addedUsingSystem: true` in the result). `generate_overrides` never
needs it.

**Through the gate, with dryRun.** Every write goes through
`MutationApplier.ApplyOrPreviewAsync(candidate, dryRun)`: the stubs are refused if they would
introduce any compile error not in the load-time baseline, and pre-existing errors they fix
(CS0535, CS0534) simply disappear. The JSON is the standard write-tool shape
(`applied, dryRun, wouldApply, changedFileCount, changes, conflicts, staleFile, message`,
gated on `result.Accepted`), plus the per-tool fields. Refusals (nothing to generate, no
abstract base, `generate_overrides` without `members`/`all`, unknown member names) return
`applied: false` with `changes: []` and a message; they are structured results, not errors.

**What SyntaxGenerator could and could not do.**

- Could: build every member kind from its symbol with the substituted types of a constructed
  interface (`IRepository<string>` gives `string? Find(string key)`), carry nullable
  annotations (`event EventHandler? Changed`, `string? ToString()`), explicit
  implementations (`AsPrivateInterfaceImplementation`), and base-call expressions.
- Could not, worked around: the symbol-based factories copy the source member's modifiers,
  and for an interface or abstract member that means `abstract`, so they silently DROP the
  bodies you pass (the method came out as `public string? Find(string key);`, CS0501).
  Fix: reset the modifiers, then re-apply bodies with `WithStatements` /
  `WithGetAccessorStatements` / `WithSetAccessorStatements`. The symbol-based
  `CustomEventDeclaration` drops add/remove bodies for the same reason, so events use the
  name-based overload. Doc comments are not something the generator handles at all (see
  above). Layout (indentation, braces, blank lines between the new members) comes from
  running the Formatter on the annotated nodes, not from NormalizeWhitespace.
- Not attempted: `init` accessors, `ref` returns, static abstract interface members beyond
  emitting `static`, and adding usings for types other than `NotImplementedException`
  (a type whose namespace is not imported stays qualified after simplification, which still
  compiles).

**Fixture.** `fixtures/GenerationSolution` (one classlib, `GenerationLib`, net10.0, implicit
usings, nullable) is separate from FixtureSolution so FixtureSolution's error-count answer keys
stay untouched. It does not compile on purpose: its 7 baseline errors (5x CS0535 for
`MemoryRepository`, 1x CS0534 for `Circle2`, 1x CS0535 for the partial `Ledger`) are exactly
the members the tools must produce, and the tests assert the count drops by exactly what each
call generates. `Ledger`'s base list is on its second part (Contracts.Part2.cs) while the
stubs go to the first (Contracts.cs), pinning "first declaration" against "declaration that
names the interface".

**Tests.** `tests/RoslynMcp.Tests/ImplementationToolsTests.cs` (answer key in its header):
exact full-file text after each generation (doc comment copied, `<inheritdoc />` otherwise),
dry run first with JSON-identical `changes` and zero bytes changed, error counts 7 -> 2
(implement_interface), 7 -> 6 (implement_abstract, interfaceName filter, partial type), 7 -> 7
(generate_overrides ToString); explicit variant; the three refusals; partial-type file choice.
Every test restores the fixture tree and asserts it byte-identical at the end.

## README subsections (ready to paste)

### `implement_interface`

Generates stubs for every interface member a class or struct does not implement yet, for the
interfaces in its base list (or only `interfaceName`), including members inherited from base
interfaces. Members already satisfied, including by a base class, are left alone and listed.
Stubs throw `NotImplementedException`, carry the interface member's XML doc comment (or
`/// <inheritdoc />`), and are appended to the type's first declaration (for a partial type the
result names the file). Only the inserted members are simplified and formatted; the rest of
the file is untouched. `using System;` is added only if `NotImplementedException` does not
already resolve (implicit usings count). Compile-gated like every write tool.

| Parameter | Default | Meaning |
|---|---|---|
| `filePath` + `line` + `column` | | the type, or any member of it |
| `fullyQualifiedName` | | instead of a position, e.g. `MyLib.MemoryRepository` |
| `interfaceName` | all | `IRepository`, `IRepository<string>` or fully-qualified |
| `explicitly` | false | emit explicit interface implementations |
| `dryRun` | false | compute + gate, report the exact changes, write nothing |

Returns `type, interfaces, alreadyImplemented, generated, insertedInto, partialDeclarationFiles,
addedUsingSystem, applied, dryRun, wouldApply, changedFileCount, changes, conflicts, staleFile,
message`. If nothing is missing it returns `applied: false` with "Nothing to generate".

```jsonc
// implement_interface { "fullyQualifiedName": "GenerationLib.MemoryRepository", "dryRun": true }
{ "type": { "name": "MemoryRepository", "kind": "NamedType", "display": "GenerationLib.MemoryRepository" },
  "interfaces": ["GenerationLib.IRepository<string>", "GenerationLib.IReadOnlyRepo<string>"],
  "alreadyImplemented": ["GenerationLib.IRepository<string>.Name", "GenerationLib.IRepository<string>.Add(string)"],
  "generated": ["GenerationLib.IRepository<string>.Find(string)", "GenerationLib.IRepository<string>.Current",
                "GenerationLib.IRepository<string>.Changed", "GenerationLib.IRepository<string>.this[int]",
                "GenerationLib.IReadOnlyRepo<string>.Count"],
  "insertedInto": ".../GenerationLib/Contracts.cs",
  "applied": false, "dryRun": true, "wouldApply": true, "changedFileCount": 1,
  "changes": [{ "file": ".../Contracts.cs", "edits": [{ "line": 37, "oldText": "",
    "newText": "\n    /// <summary>Finds the item stored under <paramref name=\"key\"/>.</summary>\n    /// <param name=\"key\">The lookup key.</param>\n    public string? Find(string key)\n    {\n        throw new NotImplementedException();\n    }\n ..." }] }],
  "message": "Dry run: the edit would be applied; 1 file(s) would change. Nothing was written." }
```

### `implement_abstract`

Generates `override` stubs for every abstract member inherited from the base-class chain that
the class does not override yet. Stubs keep the base member's accessibility, throw
`NotImplementedException`, and carry the abstract member's XML doc comment (or
`/// <inheritdoc />`). Works on an abstract class too. Refuses, writing nothing, if the class
has no abstract base; returns "Nothing to generate" if everything is already overridden.
Parameters: the type (`filePath` + `line` + `column`, or `fullyQualifiedName`) and `dryRun`.
Returns `type, abstractBases, generated, insertedInto, applied, dryRun, wouldApply,
changedFileCount, changes, conflicts, staleFile, message`.

```csharp
// implement_abstract { "fullyQualifiedName": "GenerationLib.Circle2" } appends to Circle2:
    /// <summary>Length of the outline.</summary>
    public override double Perimeter
    {
        get
        {
            throw new NotImplementedException();
        }
    }
```

### `generate_overrides`

Generates `override` members for virtual (non-abstract, non-sealed, not yet overridden)
members of the base chain, including `object`'s `Equals`, `GetHashCode` and `ToString`.
Bodies call the base member, so behaviour is unchanged until you edit them. Pass `members`
(names; every overload of a name is generated). Without `members` it **refuses** and lists the
`candidates`, unless `all: true`, so an agent never blanket-overrides `object` by accident.
Doc comments are copied as above.

| Parameter | Default | Meaning |
|---|---|---|
| `filePath` + `line` + `column` / `fullyQualifiedName` | | the type |
| `members` | | names to override, e.g. `["ToString"]` |
| `all` | false | override every candidate when `members` is not given |
| `dryRun` | false | compute + gate, report the exact changes, write nothing |

Returns `candidates` on refusal; `generated, insertedInto, applied, dryRun, wouldApply,
changedFileCount, changes, conflicts, staleFile, message` on success.

```jsonc
// generate_overrides { "fullyQualifiedName": "GenerationLib.Circle2" }
{ "type": { "name": "Circle2", ... },
  "candidates": ["GenerationLib.Shape2.Describe()", "object.Equals(object?)", "object.GetHashCode()", "object.ToString()"],
  "applied": false, "changedFileCount": 0, "changes": [],
  "message": "Not applied: pass members (names from candidates) or all: true. Refusing to override all 4 virtual member(s) by default. Nothing was written." }
```

```csharp
// generate_overrides { "fullyQualifiedName": "GenerationLib.Circle2", "members": ["ToString"] }
    /// <inheritdoc />
    public override string? ToString()
    {
        return base.ToString();
    }
```
