# v2.1: `change_signature`

Source: `src/RoslynMcp/Tools/SignatureTools.cs`. Tests: `tests/RoslynMcp.Tests/ChangeSignatureTests.cs`.
Fixture answer key: `fixtures/FixtureSolution/FixtureLib/Shipping.cs` and
`fixtures/FixtureSolution/FixtureApp/ShippingUsages.cs`.

## Description (as exposed to the client)

> Solution-wide signature change for a method or constructor: add, remove, and/or reorder
> parameters across the WHOLE override/implementation group (the definition, every override,
> every interface implementation, and the interface member itself) and rewrite every call site
> (positional and named arguments, `base.Method(...)` calls, cross-project). Operations apply in
> the order remove -> add -> reorder. Unrelated overloads with the same name are never touched.
> Usages that cannot be rewritten safely (method groups / delegate conversions,
> collection-initializer Add calls, attributes) make the tool refuse and list the locations;
> nothing is written. Compiles the result first and only writes to disk if no new compile
> errors appear - a removed parameter that is still read in a body comes back as a CS0103
> conflict, not a broken build.

It is a write-side tool and goes through the same compile-before-write contract as
`apply_rename` and `extract_interface` (`MutationApplier.TryApplyAsync`): staleness check,
in-memory compile of the affected projects, baseline comparison, then write-or-report.

## Parameters

Identify the method the same two ways `apply_rename` accepts:

| Parameter | Type | Meaning |
|-----------|------|---------|
| `filePath` + `line` + `column` | string, int, int | Position of the method/constructor name (1-based). A position on one of its parameters also works. |
| `fullyQualifiedName` | string | `Namespace.Type.Member`, or `Namespace.Type.Member(string, int)` to pick an overload (parameter types as C# display names). |

Then any combination of the three operations (at least one is required):

| Parameter | Type | Meaning |
|-----------|------|---------|
| `removeParameters` | string[] | Names (as declared on the targeted method) to remove from every declaration in the cascade and from every call site, positional or named. Not pre-scanned: a parameter still read in a body is caught by the compile gate (CS0103) and reported. |
| `addParameters` | `{ name, type, defaultValue?, callSiteValue?, index? }[]` | `type` is C# source text. `callSiteValue` is an expression inserted at every call site; `defaultValue` makes the parameter optional. With `callSiteValue` every call site gets the argument; with only `defaultValue` call sites are left unchanged; with neither the tool errors before touching anything. `index` is the 0-based position in the post-removal list; default is before the first optional/`params` parameter for a required parameter, otherwise before any `params` parameter (i.e. the end). |
| `newOrder` | string[] | The complete parameter name list in the desired final order. Must be an exact permutation of the parameters left after removals plus additions. |

Operations are applied in a fixed order: **remove, then add, then reorder.** So
`removeParameters` names refer to the original signature, `index` values refer to the
post-removal list, and `newOrder` must list the post-add/remove set.

## What gets rewritten

**Cascade.** The target's whole override/implementation group, collected the way Roslyn's own
Change Signature does: the original definition, the `OverriddenMethod` chain, every override
(`SymbolFinder.FindOverridesAsync`), every interface implementation, explicit and implicit
(`FindImplementationsAsync`), the interface member itself when the target is an
implementation (`FindImplementedInterfaceMembersAsync`), and both parts of a partial method.
If any member of the group lives outside the loaded solution (e.g. you targeted an override
of a framework method) the tool refuses - that signature cannot be changed.

**Call sites.** Every reference to any member of the group, solution-wide
(`SymbolFinder.FindReferencesAsync`): invocations through any static type, `base.Method(...)`,
`this(...)`/`base(...)` constructor initializers, `new T(...)`, target-typed `new(...)`, and
primary-constructor base calls. Argument handling:

- Positional arguments are reordered to match `newOrder`; removed parameters' arguments are
  dropped.
- Named arguments stay named and keep their textual order; they are only touched when a new
  argument has to be added or theirs is removed.
- A new `callSiteValue` argument is emitted positionally while every argument before it in
  the final order is positional; once a named argument or an omitted optional argument
  precedes it, it is emitted as `name: value`. The same rule converts an existing positional
  argument to a named one when a reorder moves it behind an omitted optional argument.
- `params` arguments in expanded form move as a block. If the change would force them behind a
  named argument the call site is reported as unsupported instead of guessed at.
- `nameof(Method)` and XML doc `cref`s are left alone (both stay valid, or at worst warn).

**Never touched:** other overloads with the same name, their call sites, string literals,
comments.

**Refused, nothing written.** If any usage of the group cannot be rewritten as an argument
list, the tool returns `applied: false` with an `unsupportedUsages` list (file, line, column,
snippet, reason) and writes nothing. That covers the method used as a method group / delegate
conversion (`Func<string,int,decimal> f = shipper.Quote;`), implicit references
(collection-initializer `Add`, pattern-based calls), attribute usages, and references that do
not bind cleanly because of a pre-existing error. Rewrite those by hand first.

## Result shape

```json
{
  "symbol":        { "name": "Quote", "kind": "Method", "display": "FixtureLib.Shipper.Quote(string, int)", "containingType": "FixtureLib.Shipper" },
  "cascade":       [ "FixtureLib.Shipper.Quote(string, int)", "FixtureLib.IShipper.Quote(string, int)", "FixtureLib.ExpressShipper.Quote(string, int)" ],
  "operations":    { "removed": [], "added": [ { "name": "insured", "type": "bool", "callSiteValue": "false" } ],
                     "before": "FixtureLib.Shipper.Quote(string, int)",
                     "after":  "FixtureLib.Shipper.Quote(string destination, int weightKg, bool insured)" },
  "callSiteCount": 5,
  "applied":       true,
  "changedFileCount": 2,
  "changes":       [ { "file": "...", "edits": [ { "line": 12, "oldText": "...", "newText": "..." } ] } ]
}
```

On a compile-gate rejection the shape matches `apply_rename`: `applied: false`,
`changedFileCount: 0`, `changes: []`, `conflicts: [ { id, message, file, line, column } ]`,
`message`. On a stale file: `staleFile` + `message`. On an unrewritable usage:
`applied: false`, `unsupportedUsages: [ { file, line, column, snippet, reason } ]`, `message`.
`conflicts`, `staleFile`, `message`, `newOrder`, `defaultValue` and `callSiteValue` are omitted
entirely when not applicable - the tool never sends explicit `null`s. Input validation
problems (unknown parameter name, bad type syntax, `newOrder` not a permutation, an add with
neither `callSiteValue` nor `defaultValue`) come back as `{ "error": "..." }` before anything
is computed.

## Worked example

Fixture: `IShipper.Quote(string destination, int weightKg)` implemented by the virtual
`Shipper.Quote`, overridden by `ExpressShipper.Quote` (whose body calls
`base.Quote(destination, weightKg)`), with an unrelated one-argument overload
`Shipper.Quote(string destination)` sitting next to it. `ShippingUsages.Exercise()` calls the
two-argument Quote through the interface, the base type, and the derived type - the last one
with named arguments in swapped order - plus the one-argument overload once.

```json
{
  "tool": "change_signature",
  "arguments": {
    "filePath": "/repo/fixtures/FixtureSolution/FixtureLib/Shipping.cs",
    "line": 18,
    "column": 28,
    "addParameters": [ { "name": "insured", "type": "bool", "callSiteValue": "false" } ]
  }
}
```

Result: `applied: true`, `cascade` lists all three declarations, `callSiteCount: 5`,
`changedFileCount: 2`. On disk:

```csharp
// FixtureLib/Shipping.cs
decimal Quote(string destination, int weightKg, bool insured);                              // interface
public virtual decimal Quote(string destination, int weightKg, bool insured) => ...;        // base
public decimal Quote(string destination) => destination.Length * 1.5m;                      // unrelated overload: byte-identical
public decimal Estimate(string destination, int weightKg) => Quote(destination, weightKg, false) + 1;
public override decimal Quote(string destination, int weightKg, bool insured) => base.Quote(destination, weightKg, false) * 2;

// FixtureApp/ShippingUsages.cs
total += viaInterface.Quote("Austin", 2, false);
total += viaBase.Quote("Dallas", 5, false);
total += viaDerived.Quote(weightKg: 3, destination: "Houston", insured: false);   // named call: new argument is named too
total += viaBase.Quote("Waco");                                                   // one-arg overload: untouched
```

The same fixture with `"removeParameters": ["weightKg"]` is **rejected**: `Shipper.Quote`'s
body still reads `weightKg`, so the gate reports `CS0103` in `conflicts` and neither file is
written. With `"newOrder": ["weightKg", "destination"]` the three declarations become
`Quote(int weightKg, string destination)`, the positional calls become `Quote(2, "Austin")`
and `Quote(5, "Dallas")`, and the named call is textually untouched and still compiles.

## Known limitations

- **Ordinary methods and constructors only.** Delegates, local functions, lambdas, operators,
  accessors and primary constructors are refused with a clear error. (Primary constructors
  would need the type's parameter list and, for records, the generated members rewritten.)
- **Method groups / delegate conversions are refused, not rewritten.** A `Func<...> f = x.M;`
  cannot be re-targeted to a different delegate shape safely. The tool lists the locations and
  writes nothing.
- **Attribute usages are refused.** Changing an attribute constructor would need the attribute
  argument list rewritten; this is reported, not attempted.
- **Implicit references** (collection-initializer `Add`, `foreach`/`await`/deconstruction
  pattern calls) have no argument list in source and are refused.
- **Call sites the compiler cannot see are not rewritten:** `dynamic` receivers, reflection,
  other solutions. The compile gate only protects what is in the loaded solution.
- **Implicit `base()` constructor calls** are not in source. Adding a required parameter to a
  base constructor makes derived constructors fail the gate (CS7036); the conflict is reported.
- **Parameter names come from the targeted method.** `removeParameters`/`newOrder` use the
  names of the method you pointed at; if an override or implementation names its parameters
  differently, its declaration is still changed by position, and named arguments at its call
  sites keep working because nothing is renamed.
- **`params` must stay last and required parameters before optional ones.** The tool does not
  enforce this itself; an illegal ordering is caught by the gate (CS0231 / CS1737) and
  reported. Use `index` when adding a required parameter to a method with optional ones.
- **XML doc `cref`s and `<param>` tags are not updated.** Both yield warnings, not errors.
- **A new argument on a named call site is appended** (`insured: false`) rather than placed
  at its declared position; the result is equivalent and keeps existing named arguments
  textually stable.
