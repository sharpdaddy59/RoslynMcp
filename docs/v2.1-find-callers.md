# find_callers (v2.1 draft, to be folded into README)

Read-side navigation, one level up from `find_references`: a transitive
**incoming call hierarchy**. Implemented in `src/RoslynMcp/Tools/HierarchyTools.cs`.

## Description text (as registered with MCP)

> Transitive INCOMING call hierarchy (who calls this, and who calls those) for a
> method, constructor, property, or event, identified by filePath+line+column or
> fullyQualifiedName. Level 1 = every member that calls the target, with exact call
> sites; level 2 = their callers, and so on to 'depth'. Dispatch-aware by default: for
> overrides, interface implementations, and virtual/abstract/interface members, callers
> that reach the target through the base or interface declaration are included and
> labeled 'via' (base.X() calls are excluded since they never dispatch down). Recursion
> is shown as a 'cycle: true' leaf; a member already shown elsewhere is marked
> 'seenBefore: true'; program entry points are marked 'isEntryPoint: true'.
> Breadth-first, deterministic, capped at maxNodes ('truncated: true' when hit).
> Read-only.

## Tool table row

| Tool | What it does |
|---|---|
| `find_callers` | Incoming call tree for a method/ctor/property/event: who calls it, who calls those, to `depth`; dispatch-aware (`via` labels), cycle- and diamond-aware, entry points marked |

## Parameters

| Name | Type | Default | Notes |
|---|---|---|---|
| `filePath` | string? | - | Absolute path; use with `line` + `column` |
| `line` | int? | - | 1-based |
| `column` | int? | - | 1-based |
| `fullyQualifiedName` | string? | - | Instead of a position, e.g. `FixtureLib.Pipeline.Execute` or `FixtureLib.Lower.Run(string)` (same resolver as `apply_rename`) |
| `depth` | int | 3 | Clamped to 1..10 |
| `maxNodes` | int | 200 | Clamped to 1..5000; total nodes in the tree |
| `includeDispatch` | bool | true | `false` = only direct callers of this exact symbol |

A position on a property accessor resolves to the property; a reduced extension
method resolves to its static definition. A type, field, local, etc. returns
`{error}`; so do a bad position and missing arguments (never a throw).

## Result shape

```jsonc
{
  "target": { "name", "kind", "display", "containingType" },
  "depth": 3,                     // effective (clamped) depth
  "includeDispatch": true,
  "dispatchGroup": [              // omitted when the target has no base/interface/override relatives
    { "member": "Trim.Run(string)",   "relation": "base" },
    { "member": "IStage.Run(string)", "relation": "interface" }
  ],
  "nodeCount": 6,
  "truncated": false,
  "roots": [                      // level-1 callers
    {
      "symbol": { "name", "kind", "display", "containingType" },
      "location": { "file", "line", "column", "snippet" },   // the caller's declaration
      "callSites": [ { "file", "line", "column" } ],          // where it calls its parent node
      "via": "IStage.Run(string)",   // only when the call reaches the parent through a dispatch relative
      "viaKind": "interface",        // base | interface | override | implementation
      "cycle": true,                 // only when this caller is already on the path; never expanded
      "seenBefore": true,            // only when this caller already appeared elsewhere (still expanded)
      "isEntryPoint": true,          // only for the compilation entry point
      "callers": [ /* same node shape, next level */ ]
    }
  ]
}
```

Optional flags/labels are omitted when false/absent. Top-level statements
(`<Main>$`) display as `Program (top-level statements)`.

Ordering is deterministic: callers sorted by their first call site's file
(ordinal), then position, then `via`, then caller display. The walk is
breadth-first, so `maxNodes` cuts the deepest levels first; `seenBefore` marks
every appearance after the first in that order.

## Dispatch semantics

For a non-static method/property/event the tool builds a dispatch group:
the target, its overridden-member chain (`base`), interface members implemented
by any of those (`interface`), and its overrides (`override`) and interface
implementations (`implementation`) from `FindOverridesAsync` /
`FindImplementationsAsync`. Direct callers of every group member are merged in;
an edge that came through a relative carries `via` + `viaKind`. A `base.X()` call
reaching the target only through a `base` relative is dropped (it is a
non-virtual call to the base body, never the override). The group is recomputed
at every level, so dispatch applies all the way up the tree.

## Worked example (from the test fixture)

`fixtures/FixtureSolution/FixtureLib/Pipeline.cs`:

```csharp
public interface IStage { string Run(string s); }
public class Lower : IStage { public string Run(string s) => s.ToLowerInvariant(); }
public class Trim : IStage { public virtual string Run(string s) => s.Trim(); }
public class HardTrim : Trim { public override string Run(string s) => base.Run(s).Replace(" ", ""); }
public static class Pipeline
{
    public static string Execute(IStage stage, string s) => stage.Run(s);                 // line 18
    public static string Twice(IStage stage, string s) => Execute(stage, Execute(stage, s)); // line 20
    ...
}
```

and `FixtureApp/PipelineUsages.cs` line 10:
`var twice = Pipeline.Twice(new HardTrim(), " A B ");`

`find_callers(fullyQualifiedName: "FixtureLib.HardTrim.Run")` returns (abridged):

```json
{
  "target": { "name": "Run", "display": "FixtureLib.HardTrim.Run(string)" },
  "depth": 3, "includeDispatch": true,
  "dispatchGroup": [
    { "member": "Trim.Run(string)", "relation": "base" },
    { "member": "IStage.Run(string)", "relation": "interface" }
  ],
  "nodeCount": 3, "truncated": false,
  "roots": [{
    "symbol": { "name": "Execute", "display": "FixtureLib.Pipeline.Execute(FixtureLib.IStage, string)" },
    "callSites": [{ "file": ".../Pipeline.cs", "line": 18, "column": 67 }],
    "via": "IStage.Run(string)", "viaKind": "interface",
    "callers": [{
      "symbol": { "name": "Twice" },
      "callSites": [{ "line": 20, "column": 59 }, { "line": 20, "column": 74 }],
      "callers": [{
        "symbol": { "name": "Exercise", "containingType": "FixtureApp.PipelineUsages" },
        "callSites": [{ "file": ".../PipelineUsages.cs", "line": 10, "column": 30 }],
        "callers": []
      }]
    }]
  }]
}
```

HardTrim's own `base.Run(s)` does not appear: it calls `Trim.Run` non-virtually.
With `includeDispatch: false` the same query returns `roots: []` (nothing calls
`Run` on a `HardTrim`-typed receiver).

## Known limitations

- **Static analysis only.** Reflection, DI containers, delegates stored and invoked
  later, event raises through `+=` subscribers, and callers outside the loaded
  solution are invisible. A method passed as a method group (`list.Select(Foo)`) shows
  the method that *mentions* it as its caller.
- **Lambdas collapse into their containing member.** A call made inside a lambda is
  attributed to the member that declares the lambda (callers of an anonymous function
  are not traceable). Local functions are kept as their own nodes.
- **Accessors collapse into their property/event.** Callers of a property include
  every read and write.
- **Dispatch is over-approximate.** Every call through `IStage.Run` is reported as
  reaching every implementation; the tool does not track which concrete type flows to
  the receiver. `override`/`implementation` relatives (callers of a derived
  override of the target) are included in the VS "Calls to / Overrides" sense and are
  labeled so a reader can discard them.
- **Depth cut is silent.** A node at the maximum depth may have callers of its own;
  only `maxNodes` sets `truncated`. Re-run from that node to continue.
- **Diamonds are re-expanded** (marked `seenBefore`), so wide diamond-heavy graphs
  consume `maxNodes` quickly; lower `depth` or raise `maxNodes`.
- Implicit calls the compiler synthesizes (e.g. `foreach` -> `GetEnumerator`,
  deconstruction, collection initializers' `Add`) are only reported where Roslyn's
  `FindReferencesAsync` reports them.
- Overload resolution by `fullyQualifiedName` is best-effort (first match wins when the
  parameter list doesn't disambiguate) - use a position for overloaded members.
