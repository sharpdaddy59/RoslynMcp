# v2.1: `delete_member`

Draft README section for the `delete_member` tool (to be folded into "v2: tools that
edit"). It closes the `find_unused_members` loop: find a dead member, then delete it
with a semantic reference check in front of the delete and the compile gate behind it.

Implementation: `src/RoslynMcp/Tools/DeletionTools.cs`. Tests:
`tests/RoslynMcp.Tests/DeleteMemberTests.cs` against the fixture files
`FixtureLib/Removable.cs` and `FixtureApp/RemovableUsages.cs`.

## Tool description (as registered)

> Safely delete a member declaration (method, constructor, property, indexer, field,
> event, nested type) or a whole top-level type, identified by position or
> fully-qualified name. Checks the whole solution for remaining references first and
> REFUSES (writes nothing, lists the reference sites) if any exist, or if the member
> implements an interface member declared in the solution or overrides an abstract
> member. Removes the declaration together with its doc comments and attributes; for a
> field/event in a multi-declarator statement only that declarator is removed. With
> force=true it deletes anyway, but the compile-before-write gate still rejects the
> edit (with the real compiler diagnostics) if anything would stop compiling. Pairs
> with find_unused_members: find, then delete.

## Parameters

| Name | Type | Default | Meaning |
|------|------|---------|---------|
| `filePath` | string? | null | Absolute path of the file containing the symbol (use with `line` + `column`) |
| `line` | int? | null | 1-based line of the symbol |
| `column` | int? | null | 1-based column of the symbol (must be on the identifier) |
| `fullyQualifiedName` | string? | null | Instead of a position: `Namespace.Type`, `Namespace.Type.Member`, or `Namespace.Type.Member(Param.Types)`, the same resolver `apply_rename` uses |
| `force` | bool | false | Delete even if references remain or a contract would break. The compile gate still applies |

## What it does

1. **Resolve** the symbol (a usage site resolves to its declaration). Metadata symbols
   and compiler-generated ones (such as an implicit default constructor) are rejected
   with an error.
2. **Reference check.** `SymbolFinder.FindReferencesAsync` over the whole solution,
   ignoring locations inside the declaration being removed (so recursion and
   self-references don't count). For a type, references to every member declared
   inside it are checked as well. References that go through a symbol that survives the
   delete are not counted: a call through `IFoo.Bar()` doesn't break when you delete
   the implementing `Foo.Bar()`, so it isn't listed (the contract check handles that
   case).
3. **Contract check.** A member that implements an interface member declared in the
   solution (explicitly or implicitly), or overrides an abstract member, is a contract.
   Deleting it would break the type (CS0535 / CS0534), and the refusal names the contract.
4. **Refuse** (when `force` is false and step 2 or 3 found anything): `applied: false`,
   the reference sites (up to 50, with `truncated`), the contracts, and a message. Nothing
   is written.
5. **Delete.** The declaration is removed with its leading trivia (doc comments; attributes
   are part of the node) and trailing end-of-line, then blank lines are fixed up:
   - Leading trivia is taken back only as far as the last blank line, so the blank line
     before the member goes with it and the one before the next member stays. A comment
     separated from the member by a blank line (a section header) is kept. Preprocessor
     directives (`#region`, `#if`) are always kept.
   - If the member was the first in its block, blank lines in front of the next member
     are also removed so no blank line is left directly after the `{`.
   - Field or event in a multi-declarator statement: only that declarator and its comma
     are removed (`private int _a = 1, _b = 2;` minus `_b` gives `private int _a = 1;`).
     The whole statement goes only when it was the last declarator.
   - Partial types and partial methods: every declaration part is removed.
6. **Compile gate.** The candidate goes through `MutationApplier.TryApplyAsync`, the same
   staleness check and compile-before-write contract as `apply_rename`. With `force: true`
   this is the last line of defense: deleting something that's still used comes back as
   real diagnostics (CS0103, CS0117, CS0246, CS0535...) in `conflicts`, and nothing is written.

## Result shape

```jsonc
{
  "symbol": { "name": "...", "kind": "Method", "display": "...", "containingType": "..." },
  "kind": "method",             // method | constructor | static constructor | finalizer | operator |
                                // conversion operator | property | indexer | field | event |
                                // class | struct | interface | enum | delegate | record | record struct
  "applied": true,
  "fileNowEmpty": true,         // only when a type was deleted and its file now declares no types
  "referenceCount": 1,          // present when references were found
  "references": [ { "file": "...", "line": 23, "column": 31, "snippet": "..." } ],
  "truncated": true,            // present when more than 50 references were found
  "contracts": [ "implements interface member FixtureLib.IRemovable.Ping()" ],
  "changedFileCount": 1,
  "changes": [ { "file": "...", "edits": [ { "line": 17, "oldText": "...", "newText": "" } ] } ],
  "conflicts": [ { "id": "CS0103", "message": "...", "file": "...", "line": 23, "column": 31 } ],
  "staleFile": "...",           // a target file changed on disk after load; reload and retry
  "message": "...",
  "note": "This symbol is publicly visible: ..."  // whenever the symbol is visible outside its assembly
}
```

Null fields are omitted, as with every other tool. `changedFileCount` is 0 and `changes`
is empty whenever `applied` is false.

**Public members.** A public member of a public type with zero references *is* deletable.
The tool reports references honestly, but it can only see the loaded solution. Every
result for an externally visible symbol carries a `note` saying that callers outside the
solution (other repos, packages, reflection, DI, serialization) can't be seen, so the
caller takes on that risk. This matches the `lowConfidence` tier of `find_unused_members`.

## Worked example

`find_unused_members` reports `FixtureLib.Removable.DeadHelper()` as `highConfidence`.
Deleting it by name:

```json
{ "fullyQualifiedName": "FixtureLib.Removable.DeadHelper" }
```

```json
{
  "symbol": { "name": "DeadHelper", "kind": "Method", "display": "FixtureLib.Removable.DeadHelper()", "containingType": "FixtureLib.Removable" },
  "kind": "method",
  "applied": true,
  "changedFileCount": 1,
  "changes": [ { "file": "/repo/fixtures/FixtureSolution/FixtureLib/Removable.cs", "edits": [ { "line": 17, "oldText": "\n    /// <summary>Unused private helper ...</summary>\n    private string DeadHelper() => \"dead\";\n", "newText": "" } ] } ]
}
```

The same request for `LiveHelper`, which `Used()` calls on line 23, is refused:

```json
{
  "symbol": { "name": "LiveHelper", "kind": "Method", "display": "FixtureLib.Removable.LiveHelper()", "containingType": "FixtureLib.Removable" },
  "kind": "method",
  "applied": false,
  "referenceCount": 1,
  "references": [ { "file": "/repo/fixtures/FixtureSolution/FixtureLib/Removable.cs", "line": 23, "column": 31, "snippet": "public int Used() => _a + LiveHelper().Length;" } ],
  "changedFileCount": 0,
  "changes": [],
  "message": "Not applied: 1 reference(s) remain in the solution. Nothing was written. Pass force: true only if you will fix those sites yourself (the compile gate will still reject an edit that leaves the solution broken)."
}
```

With `force: true` it is still not applied: the compile gate returns `conflicts` with
`CS0103` ("The name 'LiveHelper' does not exist in the current context").

## Known limitations

- **Never deletes files.** When deleting a type leaves its file with no type
  declarations, the declaration is removed and `fileNowEmpty: true` is reported, but the
  file (usings, namespace line) stays on disk. Deleting it is up to the caller.
- **Unsupported declaration kinds** return an error rather than a guess: enum members,
  local functions, locals, parameters, individual accessors, positional record members
  (primary-constructor parameters and the properties generated from them), and
  compiler-generated members.
- **Same blind spots as `find_unused_members`.** The reference check can't see
  reflection, DI containers, serialization, `nameof` in other repos, XAML/Razor markup,
  or external consumers. The compile gate catches compile-time breakage inside the
  solution, but not runtime breakage through those channels.
- **Contracts from metadata are not refused up front.** A member implementing an
  interface from a referenced package (for example `IDisposable.Dispose`) isn't flagged by
  the contract check, since the spec only covers interfaces in the solution. The compile
  gate still rejects the delete (CS0535) if it breaks the type. Overrides of *abstract*
  members are refused wherever the base is declared. Overrides of *virtual* members are
  not refused, because deleting them just falls back to the base implementation.
- **Comments are trimmed by heuristic.** Leading trivia goes back as far as the last
  blank line. A comment that sits directly above the member with no blank line between
  them is treated as part of the member and removed with it, even if it was meant as a
  section header.
- **Brace-adjacent blank-line fixup** (deleting the first member of a block) is
  implemented but not covered by a dedicated test.
